ПОЛНАЯ НАСТРОЙКА v28.10

ШАГ 1. ЗАГРУЗИТЬ ПРОЕКТ

В корень репозитория GitHub загрузите обе папки из архива:
  .github
  seb_gun_crm_render_ready

После Commit and push дождитесь успешного Deploy в Render.

ШАГ 2. НАСТРОИТЬ RENDER → ENVIRONMENT

Откройте сервис seb-gun-crm → Environment и добавьте:

TELEGRAM_BOT_TOKEN
  Новый токен бота от BotFather. Старый опубликованный токен использовать нельзя.

BLUESALES_NOTIFICATION_LOGIN
  Логин BlueSales служебного аккаунта, который имеет доступ к диалогам и клиентам.

BLUESALES_NOTIFICATION_PASSWORD
  Пароль этого аккаунта BlueSales.

NOTIFICATION_CHECK_SECRET
  Придумайте длинную случайную строку, например 32–64 символа. Не используйте пароль BlueSales.

VK_TOKEN
  Существующий токен сообщества VK. Если диалоги CRM уже работают, он обычно уже заполнен.

Сохраните Environment и дождитесь перезапуска Render.

ШАГ 3. ПОДКЛЮЧИТЬ МЕНЕДЖЕРОВ

Каждый менеджер под своим логином открывает CRM → Ещё:
  1. Нажимает «Подключить Telegram».
  2. В Telegram нажимает START.
  3. Возвращается в CRM.
  4. Включает отправку уведомлений.
  5. Проверяет SLA 8 минут и график 10:00–22:00 МСК.
  6. Нажимает «Сохранить настройки».

По умолчанию каждому менеджеру назначается только его собственный фильтр лидов.

ШАГ 4. СОХРАНИТЬ ПРИВЯЗКИ ПОСЛЕ ПЕРЕЗАПУСКА

После подключения всех менеджеров администратор открывает CRM → Ещё → «Сохранить подключения всех менеджеров» и нажимает «Скопировать для Render».

В Render → Environment добавьте:
  Key: NOTIFICATION_RULES_JSON
  Value: полностью скопированная строка

Сохраните изменения и дождитесь Deploy. После запуска в CRM поле «Постоянных подключений» должно быть больше нуля.

ШАГ 5. НАСТРОИТЬ GITHUB ACTIONS ДЛЯ БЕСПЛАТНОГО RENDER

Откройте GitHub → репозиторий seb-gun-crm → Settings → Secrets and variables → Actions → New repository secret.

Добавьте два секрета:

CRM_NOTIFICATION_URL
  https://seb-gun-crm.onrender.com

CRM_NOTIFICATION_SECRET
  Точно такая же строка, как NOTIFICATION_CHECK_SECRET в Render.

Откройте GitHub → Actions → CRM Telegram SLA → Run workflow для проверки.

ШАГ 6. ПРОВЕРИТЬ

В CRM → Уведомления должно быть:
  Фоновая проверка: Сервер настроен
  Внешний запуск: Ключ готов
  Связь после перезапуска: Сохранена

Нажмите «Проверить и отправить в бот». В сообщении должны быть клиент, менеджер лида, CRM-статус и получатель уведомления.

Важно: расписание бесплатного GitHub Actions запускается примерно каждые 15 минут. Для гарантированного уведомления ровно через 8 минут нужен постоянно работающий сервер или отдельный платный worker.
