seb_gun CRM + VK DIRECT v24.5

Главное исправление: ЗАКАЗ + УСЛУГА больше не должны ждать тяжёлый /api/meta.

Что изменено:

1. /api/meta больше НЕ сканирует всю базу клиентов BlueSales.
   Раньше meta запускал getAllCustomers(...), который мог делать много customers.get через общую очередь BlueSales.
   Из-за этого открытие заказа/услуги могло ждать десятки секунд.
   В v24.5 meta берёт users.get + уже сохранённые словари/цвета BlueSales UI.

2. Клиентский ensureMeta() дедуплицирован.
   Если несколько частей интерфейса одновременно запрашивают meta, браузер делает один запрос, а остальные ждут тот же Promise.

3. Кнопка «Новый» в ЗАКАЗ открывает форму СРАЗУ.
   Meta и каталог услуг догружаются параллельно в фоне.

4. Поиск по УСЛУГАМ больше не перерисовывает весь чат на каждую букву.
   Обновляется только список услуг.

5. /api/orders GET кэшируется на 15 секунд по клиенту.
   Повторное открытие CRM не создаёт лишний orders.get, если данные ещё свежие.

6. После orders.add очищается только кэш заказов этого клиента.
   Больше не сбрасывается весь аккаунтный кэш (meta/clients/etc.).

7. Сохранение заказа стало быстрее визуально.
   После успешного POST новая карточка показывается сразу, а контрольный GET orders идёт в фоне.

8. loadDrawerOrders() защищён от параллельных дублей.
   Если один orders.get уже выполняется, второй не запускается.

9. Добавлена диагностика очереди BlueSales.
   Если запрос простоял в очереди >= 1200 мс, сервер пишет:
   [BlueSales queue] orders.get waited XXXXms before start

10. Передача goodsPositions сделана устойчивее:
    numeric goods.id используется как id;
    строковые локальные артикулы (например A-001) отправляются как goods.marking, а не превращаются в NaN.

Проверка сборки:
- npm run check: OK
- npm test: OK
- integration-v245.js: OK
- smoke test GET /api/health: 200, version 24.5

Важно:
Официальный BlueSales API документирует orders.add / orders.get и goodsPositions в заказе.
Публичного метода списка услуг/товаров в используемом API Demo нет, поэтому выбор «УСЛУГА» остаётся локальным каталогом data/services.json, а выбранная позиция отправляется в BlueSales внутри goodsPositions по артикулу/названию.
